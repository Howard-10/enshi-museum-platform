# 项目路线图

## 已完成

1. 新目录、前后端分离、Docker 基础服务。
2. Word 文档、Excel 目录和图片、音视频资料的去重导入与审计。
3. PostgreSQL + MinIO 媒体关联、媒体短时访问链接。
4. 本地关键词检索、RRF/重排骨架、引用返回、媒体意图处理。
5. Redis + PostgreSQL 双层对话记忆。
6. 前端馆藏搜索、媒体播放和历史记录。
7. 离线检索评测、模型调用安全开关、完整容器化部署文件。

## 当前运行模式

系统运行在 `keyword_rag`：不调用外部模型，只依据本地资料返回文物、Word 引用和媒体。可通过 `GET /api/v1/system/readiness` 查看就绪状态。

## 下一阶段：模型接入

前置条件是学校确认 embedding、聊天模型和 reranker 的接口及向量维度。收到这些信息后按以下顺序推进：

1. 填写 `.env`，仍保持 `EXTERNAL_MODEL_CALLS_ENABLED=false` 做配置预检。
2. 固定向量维度、建立 pgvector 索引。
3. 小批量向量化和评测，不调用线上聊天回答。
4. 验收后启用向量召回，和现有关键词召回进行 RRF 融合。
5. 接入 reranker 后复跑评测，确认准确率提升。
6. 最后启用聊天模型生成，强制返回引用，保留无模型降级能力。

## 后台管理与权限

在真实部署前补齐登录、角色和管理端：

- 管理员：资料导入、审核、媒体关联修正、用户与角色管理；
- 编辑：文物与资料的增改、审核提交；
- 访客：只读检索与会话；
- 所有写入操作保留审计日志。

权限方式需要项目负责人确认（学校统一登录或系统本地账号）后再实现，避免先写一套以后要废弃的认证系统。
